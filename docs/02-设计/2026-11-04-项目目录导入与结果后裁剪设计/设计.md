# 1. 设计结论

本次调整拆成两条独立链路：

1. 项目目录导入：项目可以直接选择族谱根目录，根目录下的一级子目录自动作为卷；选择目录时只保存路径，不扫描图片。用户点击“创建并处理”后才执行快速结构扫描、图片登记和后台处理。
2. 结果后裁剪：原图只作为处理输入，普通矩形裁剪、单页裁剪、双页分页都在处理结果上执行。原图不再被裁剪、分页或替换；每次裁剪都生成独立的新结果页。

现有“先创建项目、再进入项目新建卷”的方式保留，作为无根目录或单卷场景的兼容入口。

# 2. 当前实现与问题

## 2.1 新建卷等待时间

当前前端在选择目录后会调用 `browseFolder` 统计图片数量并加载首张预览；浏览器选目录还会逐张上传图片。后端 `TasksService.create()` 又会：

- 读取目录并排序全部图片；
- 对每张图片调用 `sharp(...).metadata()`；
- 配置分页时立即对每张原图执行透视裁剪并写入 `split-sources`；
- 再建立图片记录。

因此，图片数量越多，用户越晚看到“创建并处理”可以完成，且当前分页已经发生在算法/AI处理之前。

## 2.2 当前分页方向

当前 `batchCrop` 是建卷参数，创建图片记录时就将一个原图拆成两张虚拟输入图。后续算法或 AI 处理的是拆分后的图片，而不是原图处理结果。该模型无法支持“100张图片中只有部分需要分页”，也会导致分页方向与用户期望相反。

# 3. 目标目录模型

示例：

```text
王氏族谱/                         项目根目录
├─ 卷一/                          卷目录，自动创建为卷一
│  ├─ 卷一图.jpg
│  └─ 卷二图.png
└─ 卷二/                          卷目录，自动创建为卷二
   └─ ...
```

约定如下：

- 项目根目录名默认作为项目名称，用户可以修改；
- 根目录下的一级子目录名作为卷名；
- 当前版本不支持卷目录下再有子目录；
- 图片只登记原路径，不复制、不改写用户原图；
- 根目录不直接放图片。根目录下的图片可忽略并在扫描报告中显示，不作为卷处理；
- 多级目录直接跳过：只处理根目录下的一级子目录，一级子目录下面的目录及其内容不进入本次导入；
- 空根目录、没有一级子目录、所有卷为空，均视为合法项目，可以创建成功，但不启动处理队列，并显示“暂无可处理图片”；
- 忽略常见隐藏/系统目录时应在界面显示忽略数量，不能静默吞掉用户实际一级卷目录；
- 读取失败的目录只记录为跳过项，不影响其他合法目录的项目创建。

## 3.1 浏览器访问服务器时的文件获取

服务部署在服务器、用户通过浏览器访问时，服务器进程无法直接读取用户电脑的本地路径。客户端选择目录后必须把文件或目录句柄内容传到服务器，不能只把 `C:\...` 路径提交给后端。

建议按能力分层：

1. 优先使用浏览器 `showDirectoryPicker` 或 `<input webkitdirectory>` 获取目录文件；客户端保留每个文件的相对路径，并创建上传会话；
2. 上传时保留相对目录层级，例如 `王氏族谱/卷一/001.jpg`，服务端将其写入服务器的临时导入目录；
3. 服务端以相对路径重新执行“一级卷目录”扫描，自动跳过二级及更深目录；
4. 只有文件上传完成并通过结构扫描后，才创建卷和图片记录；
5. 如果客户端与服务端在同一台电脑运行，才允许使用本地绝对路径模式作为快捷方式，并在界面明确显示“本机模式”。

上传策略需要支持断点/重试、文件大小校验和导入批次幂等。目录选择完成后不立即上传；用户点击创建时才开始上传和导入。

# 4. 项目导入流程

## 4.1 前端交互

项目新建弹窗增加“族谱根目录”字段：

1. 用户选择或填写根目录；
2. 选择完成后只显示路径，不自动统计图片、不加载首张图、不上传图片；
3. “创建项目并处理”按钮立即可点击；
4. 点击后显示“正在检查目录结构”，接口快速返回导入任务 ID；
5. 项目卡片立即出现，项目/卷状态显示为“扫描中”；
6. 扫描完成后自动创建卷并按顺序进入全局处理队列；
7. 结构错误显示到项目级错误面板，并指出具体路径；用户修复目录后可点击“重新扫描”。

原有新建卷弹窗不删除：未选择根目录时，仍按当前模式创建单卷。单卷入口也改为“点击创建时扫描并登记”，不再在选目录时等待。

## 4.2 后端分阶段接口

建议增加项目导入接口，不把所有工作塞入原有同步 `POST /tasks`：

### `POST /tasks/projects/import`

请求核心字段：

```json
{
  "name": "王氏族谱",
  "surname": "王",
  "rootPath": "D:/族谱/王氏族谱",
  "autoStart": true,
  "volumeDefaults": {
    "useAi": false,
    "useAiClean": false,
    "processingEnabled": true
  }
}
```

接口只做来源检查、目录结构扫描和导入任务创建，然后快速返回：

```json
{
  "projectId": 123,
  "importJobId": "...",
  "status": "scanning"
}
```

### `GET /tasks/projects/:pid/import-status`

返回扫描/登记/排队进度：

```json
{
  "status": "importing",
  "totalVolumes": 2,
  "readyVolumes": 1,
  "totalImages": 1200,
  "registeredImages": 820,
  "errorCount": 0,
  "message": "正在登记卷一图片"
}
```

### 失败与重试

- 目录中只有空内容：导入任务成功，项目状态为 `ready`，不启动处理队列；
- 多级目录：记录为跳过项，导入任务仍可成功；
- 某一卷读取失败：记录为跳过项，其余合法卷可以继续；项目显示“部分跳过”；
- 进程中断：导入任务可从最后登记的文件继续，不能重复插入图片记录；
- 通过唯一键或导入批次校验 `task_id + source_path`，保证重试幂等。

## 4.3 图片登记策略

目录扫描分两步：

1. 快速结构扫描：只读取根目录和一级子目录的目录项，识别一级卷、空卷、根目录图片和被跳过的多级目录；不把多级目录视为错误；
2. 后台登记：逐卷读取图片文件名并写入 `task_images`。登记阶段只记录 `source_path/file_name/sort_order`，图片宽高改为按需读取或在处理时补齐，不再为上千张图片同步调用 `sharp.metadata()`。

同机模式可以直接登记原路径；服务器模式必须使用上传会话中的服务器文件路径，数据库不能保存客户端不可访问的本地绝对路径。

# 5. 处理与裁剪/分页流水线

目标流水线如下：

```text
原图登记
  ↓
算法/AI处理（输入永远是原图）
  ↓
得到完整处理结果
  ↓
按用户选择执行普通矩形裁剪、单页裁剪或双页分页
  ↓
生成 -1 / -2 结果文件与派生页记录
  ↓
审阅、确认、导出
```

## 5.1 原图与结果的职责

- `source_path` 永远指向用户原图；
- 算法/AI 读取 `source_path`，输出完整结果到 `result_path`；
- 结果裁剪只读取 `result_path`，不调用原图裁剪逻辑；
- 裁剪/分页不会修改 `source_path`，也不会把派生图重新作为下一次算法/AI输入；
- 如果用户重新处理，先重新生成完整结果，再按已保存的裁剪配置重新生成派生结果。

## 5.2 三种结果后处理

三种操作的共同规则：

- 输入统一是当前完整处理结果或上一次裁剪生成的结果；
- 每次确认都生成一张新的派生结果，不覆盖输入；
- 同一张结果可以连续裁剪多次，形成结果链；
- 原图和完整处理结果始终保留，裁剪链可以单独删除或重新生成。

### A. 普通矩形裁剪

这是默认、最高频的模式，适用于版式标准、无需透视校正的分页：

- 在结果图上显示一个可拖动、可缩放的矩形框；
- 矩形框模板全局缓存，默认记住上次位置、尺寸比例和旋转角；
- 用户可以先在右侧拖框并确认，生成一张新结果；再回到同一输入结果，在左侧拖框并确认，生成另一张新结果；
- 两次裁剪互不覆盖，第二次裁剪的输入默认仍是原完整处理结果，也可以明确选择以上一次裁剪结果继续裁剪；
- 普通矩形裁剪不做透视变换，只执行旋转后的矩形截取；
- 如果作为分页使用，按确认顺序或用户指定顺序生成 `原文件名-1.png`、`原文件名-2.png`。

为了避免“全局缓存”的框污染不同图片，模板保存的是归一化框和输出尺寸；当前图片的框位置可以继承模板，也允许单独调整。

### B. 固定框单页裁剪

用于统一去除边缘、保留固定版式的场景：

- 在处理结果上显示可旋转底图和裁剪框；
- 裁剪框保存为模板，模板包含 `frameWidth/frameHeight`、宽高比、默认旋转角和归一化四点；
- 可保存为用户全局模板，也可保存为项目默认模板；
- 输出尺寸按模板固定，避免不同图片拖出不同尺寸；
- 单页输出命名为 `原文件名-1.png`；重复裁剪时使用下一个派生序号或用户指定名称，避免覆盖完整处理结果。

### C. 双页分页

用于一张处理结果中包含两页的场景：

- 复用当前四点透视框和任意角度旋转能力；
- 输入改为完整处理结果；
- 输出按阅读顺序命名为 `原文件名-1.png`、`原文件名-2.png`；
- 不再对分页结果再次执行算法/AI处理；
- 只有用户选中的图片执行分页，未选中的图片保留完整处理结果；
- 双页分页一次生成两张派生结果，普通矩形裁剪则可以分两次分别生成。

三种操作都应支持“只应用当前图片”和“应用到所选图片”。批量应用时使用模板，不把第一张图片的实际像素坐标直接硬套到其他尺寸图片上。

## 5.3 数据模型建议

尽量兼容现有 `task_images` 字段，增加以下字段或等价结构：

- `parent_image_id`：派生页的直接输入结果记录；
- `root_image_id`：派生链最初对应的原始图片记录；
- `image_role`：`source_result` 或 `derived_page`；
- `post_process_type`：`none`、`rect_crop`、`single_crop`、`split`；
- `post_process_config`：旋转角、四点、模板 ID、输出尺寸等 JSON；
- `output_index`：`1` 或 `2`；
- `source_result_path`：派生页所依据的完整处理结果路径。

现有 `original_source_path/split_quad` 可以继续用于兼容历史数据，但新数据不应再通过改写 `source_path` 表示原图分页。建议保留完整结果文件和派生文件，删除/重新生成派生文件时不影响原图和完整结果。

新增用户级裁剪模板表 `crop_templates`：

```text
id, user_id, name, type, frame_width, frame_height,
aspect_ratio, default_rotation, config_json, created_at, updated_at
```

模板中的几何坐标统一使用 0~1 归一化坐标；输出宽高单独保存，避免原图分辨率不同造成框尺寸漂移。裁剪结果记录输入结果 ID 和操作配置，形成可追溯的结果链。

# 6. 状态与计数

项目导入和卷处理状态建议分开：

- 项目导入：`idle/scanning/importing/ready/partial_failed/failed`；
- 卷处理：沿用 `pending/processing/reviewing/completed/failed`；
- 图片：增加 `registered/processing/ready/derived/confirmed/failed`，或用现有状态加派生字段区分。

卷的 `total_count` 应按原始图片数统计；分页后的派生页单独统计 `derived_count`。审阅页可以显示“原图 100 张，派生页 134 张”，避免用户误以为分页前就有 134 张待处理图片。

# 7. 验收标准

1. 选择包含 2 个卷、每卷上千张图片的根目录后，前端不会在选择完成后长时间卡住；创建按钮可立即操作。
2. 服务器部署时，选择的本地目录会通过浏览器上传到服务器，服务端不会尝试读取客户端的 `C:\...` 路径。
3. 空根目录、空卷、所有卷为空都能成功创建项目，并显示暂无待处理内容。
4. 多级文件夹被跳过，不创建对应卷，也不阻断其他一级卷的导入。
5. 合法根目录能自动创建项目和卷，卷名等于一级子目录名；原有单卷创建模式仍可用。
6. 一张图片配置为分页、另一张不分页时，只有前者生成 `-1/-2`，后者保留一个完整处理结果。
7. 算法/AI处理日志和输入路径均指向原图；分页和普通裁剪日志的输入路径指向处理结果。
8. 同一完整结果可以先裁右侧、再裁左侧，两次均生成独立结果，互不覆盖。
9. 重新处理后可以根据已保存模板重新生成派生页，且不会修改用户原图。
10. 固定框模板可跨图片复用，并保持配置的输出宽高；分页支持任意角度旋转和四点透视。
11. 导出结果只导出用户选择的完整结果或派生页，不重复导出原图裁剪中间文件。

# 8. 实施顺序建议

1. 先改处理数据模型和流水线：取消建卷时原图分页，补齐“处理结果后分页”的单图接口。
2. 再改审阅工作台：增加按图片选择、模板保存/复用、对结果执行普通矩形裁剪/单页裁剪/双页分页，并支持连续裁剪。
3. 增加服务器模式上传链路：保留相对目录、断点重试、导入批次幂等和跳过多级目录。
4. 最后改项目根目录导入：异步导入任务、空项目状态、自动创建卷和状态展示。
5. 增加历史数据兼容迁移：旧分页记录继续可查看，新操作按新模型写入。

本设计待确认项：根目录直接存在的图片本文按“忽略并在扫描报告显示”设计；如果希望将其作为独立卷，可以再增加“根目录图片卷”开关。
